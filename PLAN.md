# PLAN — strict-exam-output-grading v2

Working handoff for building the generic exam-grading skill in this repo.
Supersedes `Humanizer IICAETE/OPENCODE_SKILL_HANDOFF.md`.

## Goal

Grade any exam, provided that:

1. the exam questions and rubric are supplied and pass the readiness gate, and
2. student results are in a folder (local or otherwise accessible).

The EDA numerical-methods exam remains a completed example profile only; its
weights must never be applied to another exam.

## Decisions

- Skill name: `strict-exam-output-grading` (kept).
- Repo: this workspace (`Exam Checker`). Skill source of truth lives at
  `.opencode/skills/strict-exam-output-grading/`, which OpenCode discovers
  automatically when run from this repo — no `opencode.json` needed.
- Results input: local/accessible folders first. Google Drive only through a
  configured MCP connector, never required.
- Deliverables default: XLSX gradebook (plus numerical-checks sheet) and
  per-student feedback; CSV + Markdown fallback when no writer exists.
- Validation fixtures are synthetic only. No real student data in this repo.
- UX v2: the skill builds the rubric profile itself during a two-step intake
  (questions + rubric first, then the results folder) and proceeds
  automatically when the rubric is explicit and the gate passes, pausing only
  on ambiguity. Default output `./grading-run/` (never into the results
  folder). `/grade-exam` command added for one-line invocation.

## Install / use

- This repo: quit and restart OpenCode here; config and skills are loaded at
  startup, not hot-reloaded. The skill is then discoverable.
- Any project: copy `.opencode/skills/strict-exam-output-grading/` into
  `<project>/.opencode/skills/` or `~/.config/opencode/skills/`.
- Other harnesses: use the folder (or the zip) as skill/context files; see
  `references/provider-adapter.md`.

## Boundaries

- Excluded evidence types (for example video) are never opened or scored and
  are removed from the denominator.
- Missing or uncertain submissions become pending, never zero.
- No grade writes to any destination unless requested; read-back verification
  required for every write.
- Synthetic fixtures only; keep student data out of this repo.
